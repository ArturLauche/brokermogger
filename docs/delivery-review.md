# Delivery review corrections

The automated findings on PR #35 were checked against the implementation and real PostgreSQL behavior. Suggestions were treated as reports to verify, not as instructions to follow. The fixes preserve explicit approval, ownership, immutable proof and mock-only verification.

| Finding                                                                                                 | Verified behavior and correction                                                                                                                                                                                                                                                                                                                                             | Regression evidence                                                                                                                                                                                 |

| [Onboarding bounds](https://github.com/ArturLauche/brokermogger/pull/35#discussion_r4152808819)         | The service already enforced 30 identifiers and persistence already deduplicated them. Raw text was split before that boundary. Four shared 8,192-character field limits now apply before splitting; early deduplication uses the same normalization as persistence, and the combined limit has a field-linked error. The form supports all 30 permitted full-length values. | Five parser tests cover raw bounds, combined limits, normalization, source mapping and the full permitted input. Existing onboarding tests exercise concurrent completion and transaction rollback. |
| [Deletion audit atomicity](https://github.com/ArturLauche/brokermogger/pull/35#discussion_r4152809185)  | Access blocking and scheduling were already atomic, but their audit was a separate commit. A narrow audit writer now appends the mandatory hash-chained proof inside the deletion transaction.                                                                                                                                                                               | Injected queue and audit failures prove that account status, session revocation, scheduling and proof commit together or roll back. Existing chain tests still verify concurrent writers.           |
| [Deletion retry recovery](https://github.com/ArturLauche/brokermogger/pull/35#discussion_r4152809596)   | Operators could already retry failed jobs. A repeat deletion request now also rearms a terminal cleanup job while preserving the original date. It leaves pending/backoff attempts and live leases intact; token revocation only uses the original address on the first request.                                                                                             | A failed job resumes with cleared failure state and unchanged request date; a subsequent repeat does not replace a running lease.                                                                   |

Granted reads now audit first and select only consent metadata. Owners retain their full proof; pending deletion blocks stale reads.                                                                                                                                                | Query assertions exclude text, evidence, identity and hash fields. | [Monthly quota rollback](https://github.com/ArturLauche/brokermogger/pull/35#discussion_r4152810375)    | The draft caller already aborted on rejection. The repository nevertheless swallowed the monthly rollback signal inside a caller-owned transaction. | [Unfinished purge batching](https://github.com/ArturLauche/brokermogger/pull/35#discussion_r4152810727) | A sweep previously processed one 100-file page. It now drains bounded pages, counts unfinished work, reports backlog accurately and resumes promptly. Recurring scheduling honors that continuation.                                                                                                                                                                         | Real encrypted-object fixtures verify 125-file cleanup, a nonmutating dry run and a 2,001-file backlog that completes across two bounded passes.                                                    |

CI now migrates a dedicated `bm_e2e_workflows` schema for browser journeys, preserving production queue ordering and real fenced worker execution. The standalone server and browser worker fixtures continue sharing one absolute encrypted-storage path.
