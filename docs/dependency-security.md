## One expiring development exception

As of the inventory date, GitHub's reviewed braces advisory lists no patched
release and the npm registry's latest version is 3.0.3. The flaw is stack
exhaustion from attacker-controlled deeply nested glob patterns. Neither the
application nor worker imports these installed glob packages. ESLint uses
repository-controlled file patterns; shadcn is a developer component generator
(its CSS import does not start its CLI/MCP server). Do not feed untrusted glob
patterns to these tools or expose the generator as a service.

The exception is **only** GHSA-vfj7-8cjw-p6xm at high severity, braces **3.0.3**, and
the enumerated development-only dependent paths. Owner: **ArturLauche, repository
maintainer**. It expires **2026-11-11 00:00 UTC**. The owner must replace it with a
patched upstream release or remove the affected tooling before expiry; expiry
automatically blocks CI. It does not assert the package is fixed or vulnerability-free.

`npm run audit:dependencies` always runs the upstream full `npm audit --json
--audit-level=moderate --include=dev`, including when `NODE_ENV=production` would
otherwise omit development dependencies. Its policy validates the report and
lockfile, bounds each node/cause array to 100 unique entries, checks every
affected node is dev-only, and recursively checks that every cause is this exact
advisory. New advisories (even in these packages), production paths, missing lock
entries, unsupported versions, severity changes, registry errors and expired
exceptions fail. CI separately runs the unfiltered production audit at moderate
severity. Regression tests exercise each boundary. No blanket package exclusion
or global threshold reduction is used.

The raw full `npm audit --audit-level=moderate` still reports eight high package
entries caused by this one unpatched advisory and exits unsuccessfully. Report
this honestly. The policy gate distinguishes that documented exception from a
clean raw scan; the production scan has zero vulnerabilities after the updates.

The separately repaired #39 updates shadcn to 4.21.1, which extracts part of the
same CLI into `@shadcn/registry`. Its verified dev-only glob paths cause a ninth
dependent entry for the same braces advisory; that specific wrapper is included
in the exception too. There is no additional excepted advisory.
